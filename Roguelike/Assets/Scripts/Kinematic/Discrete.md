## 구현 방향

Discrete는 요청한 변위를 먼저 적용하고, 이동 후 위치에서 겹친 형상을 MTV로 분리한다. 이동 경로의 최초 접촉 시점을 구하지 않으므로, 도착 위치에 겹침이 없다면 경로 중간의 통과는 검출하지 않는다.

Teleport와 시작부터 존재한 겹침은 [공통 솔버](RuntimeFlow.md)에서 먼저 처리한다. 이 문서는 그 이후 요청 이동으로 생긴 겹침을 처리하는 방식을 설명한다.

## dt·이동 속도와 충돌 감지

게임 로직이 속도에 `dt`를 곱해 이동량을 계산하면, `dt`가 커지거나 이동 속도가 빨라질수록 한 번에 이동할 거리도 커진다. Discrete는 그 이동을 전부 적용한 뒤의 위치에서만 겹침을 검사하므로, 한 번의 이동으로 장애물을 완전히 지나치면 충돌 감지를 놓칠 수 있다.

이동 경로에서는 충돌했더라도 도착 위치에 겹침이 없으면 접촉 정보와 MTV가 생성되지 않는다. 따라서 MTV 보정의 반복 횟수를 늘리는 것만으로 이런 누락을 해결할 수는 없다. 현재 구현에는 이동을 작은 구간으로 나누는 substep 처리도 없다.

Sweep은 같은 큰 변위에 대해 경로 중간의 최초 접촉을 검사한다. Discrete와 Sweep의 충돌 감지 차이는 `dt` 값을 직접 비교해서가 아니라, `dt`와 속도로 결정된 변위를 어느 범위에서 검사하는지에 따라 발생한다.

## 처리 흐름

| 순서 | 처리 |
| --- | --- |
| 1 | 모든 동적 바디의 요청 이동량 소비 및 저장 |
| 2 | 모든 동적 바디에 요청 이동량 전체 적용 |
| 3 | 동적·정적 접촉 검사 및 동적 바디 보정 |
| 4 | 동적·동적 접촉 검사 및 보정 분담 |
| 5 | 3~4번 반복. 접촉 보정이 없으면 종료 |

이동 후 보정은 최대 16회 반복한다. 한 번의 보정으로 다른 형상과 겹칠 수 있기 때문에 다시 검사한다. 현재 구현은 접촉을 순서대로 보정하며, 모든 접촉을 모아서 한 번에 최적화하는 방식은 아니다.

## 정적 바디와의 접촉

이동 후 Bounds로 QuadTree를 조회하고, 실제로 겹친 정적 바디의 MTV 전체를 동적 바디에 적용한다. 정적 바디는 이동하지 않는다.

$$
position_A\mathrel{+}=\mathrm{MTV}
$$

솔버에 저장한 이동량에도 정적 MTV를 더한다. 이 값은 이후 동적 쌍의 보정 가중치에 사용되므로, 원래 요청만이 아니라 이번 Discrete 단계에서 이미 적용한 보정도 반영한다.

한 회차의 후보 목록은 조회 시점의 Bounds로 정해진다. 보정 후 새로 가까워진 정적 바디는 다음 반복의 조회에서 발견할 수 있다.

## 동적 바디끼리의 보정 분담

현재 접촉의 법선 `n`은 A를 B에서 분리하는 방향이다. 솔버에 저장한 A와 B의 이동량을 `dA`, `dB`라고 할 때 표면 안쪽으로 향한 성분을 가중치로 사용한다.

$$
w_A=\max(0,-d_A\cdot n),\qquad w_B=\max(0,d_B\cdot n)
$$

가중치 합이 충분하다면 각각의 비율로 MTV를 나눈다.

$$
W=w_A+w_B
$$

$$
correction_A=\mathrm{MTV}\frac{w_A}{W},\qquad
correction_B=-\mathrm{MTV}\frac{w_B}{W}
$$

A는 법선 방향으로, B는 반대 방향으로 보정한다. 두 보정의 상대 차이는 MTV 전체가 되므로 해당 접촉의 침투 깊이를 해소한다. 가중치 합은 접촉 전 간격을 좁힌 이동까지 포함할 수 있어 침투 깊이와 같은 값일 필요가 없다.

이는 질량이나 반발력을 이용한 물리 응답이 아니라, 이동에 따라 위치 보정을 나누는 정책이다. 보정 결과는 각 위치와 저장한 이동량에 함께 더한다. 따라서 뒤에 처리하는 접촉은 앞서 적용된 보정도 고려한다.

## 가중치를 얻지 못했을 때

안쪽 성분의 합이 `1e-6` 이하이면 각 이동량의 길이를 가중치로 사용한다. 현재 법선 기준으로 안쪽 성분이 없더라도, 이번 단계에서 이동한 바디들이 남은 겹침을 분담하도록 한 처리다.

이때 이동량이 0인 바디는 가중치도 0이므로 보정하지 않는다. 길이 가중치의 합도 `1e-6` 이하이면 해당 동적 접촉의 보정을 건너뛴다. 시작부터 정지한 바디가 겹친 경우를 절반씩 분리하는 [초기 겹침 해소](RuntimeFlow.md)와는 정책이 다르다.

이동 후 서로 지나쳐 중심 순서와 법선이 뒤집히면, 이동의 안쪽 성분도 달라질 수 있다. 이 정책은 최종 겹침을 기준으로 보정하며, 원래 경로에서 어느 쪽이 먼저 충돌했는지를 복원하지 않는다.

## 동적 보정 예시

반지름이 각각 `0.5`인 A와 B의 시작 중심을 `(0, 0)`, `(2, 0)`으로 두고, 요청 변위를 `(1.2, 0)`, `(-0.2, 0)`으로 둔다. 이 예시에는 정적 접촉이 없다.

| 단계 | 결과 |
| --- | --- |
| 이동 후 중심 | A `(1.2, 0)`, B `(1.8, 0)` |
| 중심 거리 / 침투 깊이 | `0.6` / `0.4` |
| A의 분리 법선 / MTV | `(-1, 0)` / `(-0.4, 0)` |
| 안쪽 이동 가중치 | A `1.2`, B `0.2`, 합 `1.4` |
| A의 보정 | `(-0.4, 0) × 1.2 / 1.4 ≈ (-0.342857, 0)` |
| B의 보정 | `(0.4, 0) × 0.2 / 1.4 ≈ (0.057143, 0)` |
| 최종 중심 | A `(0.857143, 0)`, B `(1.857143, 0)` |
| 시작 위치 대비 최종 변위 | A `(0.857143, 0)`, B `(-0.142857, 0)` |

최종 중심 간 거리는 `1`이 되어 두 원이 접한다. 수치는 표시를 위해 반올림한 값이다.

## 모서리 보정이 이동 방향을 바꾸는 경우

중심 `(0, 0)`, half extents `(1, 1)`인 정적 박스가 있다. 반지름 `0.5`인 원이 `(1.6, 1.2)`에서 `(-0.4, 0)`만큼 이동하면 도착 중심은 `(1.2, 1.2)`다.

이 위치에서는 박스의 모서리 `(1, 1)`과 겹치므로 법선이 대각선으로 나온다. [원·박스 MTV 계산](CollisionAndMTV.md)에 따라 다음 보정이 적용된다.

| 항목 | 결과 |
| --- | --- |
| 요청 변위 | `(-0.4, 0)` |
| 이동 후 중심 | `(1.2, 1.2)` |
| 분리 법선 | `(1/√2, 1/√2)` |
| MTV | `(0.153553, 0.153553)` |
| 최종 중심 | `(1.353553, 1.353553)` |
| 시작 위치 대비 최종 변위 | `(-0.246447, 0.153553)` |

요청에는 Y 이동이 없지만 최종 결과에는 Y 이동이 생긴다. Discrete는 겹친 형상을 분리할 벡터를 더하기 때문이다. Sweep의 접촉 시점에서 잔여 이동을 투영하는 방식과 결과가 달라질 수 있다.

## 얇은 장애물을 통과하는 경우

반지름 `0.5`인 원이 `(0, 0)`에서 `(6, 0)`만큼 이동하고, 장애물은 중심 `(3, 0)`, half extents `(0.25, 2)`인 박스라고 가정한다.

| 방식 | 결과 |
| --- | --- |
| Discrete | 도착 중심 `(6, 0)`에서 장애물과 겹치지 않아 보정하지 않음 |
| Sweep | 장애물 왼쪽 면 `x = 2.75`에 원이 닿는 중심 `x = 2.25`에서 정지 |

Discrete에는 경로 검사나 이동량을 작은 단계로 나누는 substep 처리가 없다. 이 때문에 큰 변위로 얇은 장애물을 통과하는 tunneling이 가능하다.

## Sweep과의 비교

| 구분 | Sweep | Discrete |
| --- | --- | --- |
| 검사 기준 | 현재 위치에서 남은 이동 경로 | 요청 이동을 적용한 뒤의 위치 |
| 주요 계산 | 접촉 비율과 법선 | 침투 깊이와 MTV |
| 이동 제한 | 접촉까지 진행하고 안쪽 성분 제거 | 이동 후 분리 벡터 추가 |
| 동적 바디 | 상대 이동량으로 접촉 시점 검출 | 최종 겹침과 이동 가중치로 보정 분담 |
| `dt`·속도에 따른 큰 변위 | 경로 중간의 접촉을 검사하여 도착 위치만 검사하는 누락 방지 | 도착 위치가 분리되어 있으면 중간 통과 미검출 |
| 공통 단계 | Teleport와 초기 겹침 해소 후 실행 | Teleport와 초기 겹침 해소 후 실행 |

어느 방식이든 현재 형상과 반복 정책에 맞춰 결과가 정해진다. 두 모드가 항상 동일한 최종 위치를 반환한다고 가정하지 않는다.
