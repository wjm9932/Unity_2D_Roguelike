## 구현 방향

정적 바디를 공간별로 저장하여 가까운 충돌 후보만 조회하는 Broad Phase 자료구조다. 조회에서 Bounds가 겹친다고 실제 형상이 충돌하는 것은 아니다. 정확한 원·박스 판정은 조회 결과에 대해 솔버나 Cast가 수행한다.

정적 바디는 등록 후 공간 위치가 바뀌지 않는 전제로 트리에 저장한다. 동적 바디는 별도의 목록에 보관하고, 동적 쌍은 목록 순회로 검사한다. 따라서 이 트리는 동적 바디까지 매 프레임 재삽입하는 구조가 아니다.

## AABB의 역할

| 연산 | 의미 |
| --- | --- |
| `Create(center, extents)` | 중심에서 extents만큼 빼고 더해 min/max 생성 |
| `Overlaps(other)` | 두 영역이 교차하거나 경계에 닿는지 검사 |
| `Contains(other)` | 다른 Bounds 전체가 자신의 영역 안에 있는지 검사 |
| `GetSweptBounds(delta)` | 시작 Bounds와 끝 Bounds를 모두 포함하는 경로 영역 생성 |

원은 반지름을 양 축 extents로 사용하고, 박스는 half extents를 사용한다. AABB의 겹침은 경계 포함 검사이며, 접촉 판정의 양수 침투 조건과는 다르다.

Swept Bounds는 실제 형상을 계속 추적한 결과가 아니라 전체 경로를 포함하는 보수적인 사각형이다. 대각선 이동에서는 실제 경로 밖의 후보도 포함될 수 있으며, Narrow Phase에서 이를 거른다.

## 노드 분할

각 노드는 영역 Bounds, 그 노드에 직접 저장한 바디 목록, 선택적인 네 자식 노드를 가진다. 영역 중심으로 나누어 네 사분면을 만든다.

| 현재 설정 | 의미 |
| --- | --- |
| `maxPerNode = 1` | Leaf의 직접 저장 수가 1을 초과하면 분할 시도 |
| `maxDepth = 6` | 루트 깊이 0부터 시작하여 깊이 6에서 추가 분할 중단 |

최대 깊이는 모든 바디를 그 깊이까지 내려보내는 목표가 아니다. 저장 수와 완전 포함 조건에 따라 더 위에 남을 수 있다. 최대 깊이에 도달한 Leaf는 여러 바디를 보관할 수 있다.

## 삽입과 재분배

| 순서 | 처리 |
| --- | --- |
| 1 | 바디 Bounds 전체가 루트 Bounds 안에 있는지 확인 |
| 2 | 자식이 있고 한 자식에 완전히 들어가면 그 자식으로 재귀 삽입 |
| 3 | 어느 자식에도 완전히 들어가지 않으면 현재 노드에 저장 |
| 4 | Leaf의 저장 수가 임계치를 넘고 최대 깊이 전이면 분할 |
| 5 | 기존 바디 중 한 자식에 완전히 포함되는 바디만 아래로 재분배 |

자식 경계를 걸치는 바디는 부모에 남는다. 여러 자식에 같은 바디를 복제 저장하지 않으므로, 일반적인 한 번의 등록에서 조회 결과를 따로 중복 제거할 필요가 없다. 중복 등록 자체를 막는 기능은 현재 없다.

예를 들어 루트가 `[-10, 10] × [-10, 10]`일 때 중심 `(0, 0)`, half extents `(1, 1)`인 박스는 중앙의 X/Y 분할선을 모두 걸친다. 어느 사분면에도 완전히 포함되지 않으므로 루트에 남는다.

루트 밖에 일부라도 걸친 바디는 현재 `Insert()`에서 등록되지 않고 반환된다. 월드 초기화 Bounds는 중심만이 아니라 정적 형상의 전체 영역을 포함해야 한다. 트리의 자동 확장 기능은 없다.

## 조회

공개 `Query(bounds, results)`는 전달된 결과 목록을 먼저 비운다. 이후 검색 영역과 노드 Bounds가 겹치지 않으면 그 노드의 탐색을 중단한다.

노드에 직접 저장한 바디를 먼저 검사하고, 바디 Bounds가 검색 영역과 겹치면 결과에 추가한다. 자식이 있으면 각 자식에 같은 검사를 반복한다. 부모에 남아 있는 경계 걸침 바디도 이 과정에서 빠짐없이 확인한다.

호출하는 쪽은 결과 목록을 재사용할 수 있다. 현재 솔버와 Cast는 각각의 목록을 보관하여 조회마다 새 결과 목록을 생성하지 않는다. 트리의 Query 자체가 목록을 초기화하므로 결과가 호출 사이에 누적되는 API는 아니다.

## 제거와 정리

제거는 현재 노드의 목록에서 대상 바디를 먼저 찾는다. 없다면 Bounds가 완전히 포함되는 자식으로 내려간다. 비어 있는 노드를 다시 합치는 Merge는 현재 구현하지 않는다. 빈 노드도 조회 조건에 따라 탐색할 수 있지만, 그 자체가 잘못된 후보를 추가하지는 않는다.

`Clear()`는 루트 참조를 제거하여 노드와 바디 목록을 더 이상 트리에서 참조하지 않도록 한다. 루트를 새로 만드는 reset 동작은 아니므로 해제된 트리를 다시 조회하는 전제로 사용하지 않는다. 월드 재초기화 시에는 새 트리를 만든다.

정적 바디의 위치나 크기가 바뀌면 저장된 노드와 실제 Bounds의 관계가 달라진다. 현재 트리에는 이를 자동 갱신하는 처리가 없으므로, 정적 바디를 움직일 경우의 재등록 정책은 별도로 필요하다. 현재 바디는 생성 후 기준 위치와 형상을 외부 Transform 변경에서 자동으로 다시 읽지도 않는다.
