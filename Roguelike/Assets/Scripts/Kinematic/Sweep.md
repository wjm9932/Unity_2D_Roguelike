## 구현 방향

Sweep은 이동 경로에서 가장 이른 접촉을 찾고 그 위치까지만 이동한다. 접촉 후에는 남은 변위의 표면 안쪽 성분을 제거하여 표면을 따라 이동할 수 있도록 한다.

현재 솔버는 바디 하나의 전체 이동을 끝낸 뒤 다음 바디를 처리하지 않는다. 모든 동적 바디의 남은 이동량을 보관하고, 전체 접촉 중 가장 이른 시점까지 모든 바디를 함께 진행시킨다. 동적 바디끼리 움직이는 과정의 접촉을 같은 진행 비율에서 처리하려는 방식이다.

## dt·이동 속도와 충돌 감지

게임 로직이 속도에 `dt`를 곱해 변위를 계산하면, `dt`나 이동 속도가 커질수록 한 번에 움직일 거리도 길어진다. Sweep은 도착 위치에 겹침이 있는지만 확인하지 않고 시작 위치부터 도착 위치까지의 경로를 검사한다.

따라서 요청 이동의 도착 위치가 장애물 너머에 있더라도, 경로 중간에서 닿는 접촉을 검출하여 그 위치까지만 이동한다. 큰 `dt`나 빠른 이동 때문에 한 번에 장애물을 완전히 지나쳐 도착 위치에서 충돌을 놓치는 Discrete 방식의 tunneling을 방지하려는 방식이다.

이 설명은 지원하는 원·축 정렬 박스와 직선 변위에 대한 경로 검사를 전제로 한다. 충돌 후보가 정상 등록되어 있어야 하며, 수치 오차와 반복 제한을 포함한 모든 상황에서 감지가 완전하다는 보장은 아니다. `dt` 자체는 솔버의 입력이 아니며, 그 결과로 요청된 이동량에 대해 검사한다.

## 처리 흐름

Teleport와 초기 겹침 해소는 [공통 솔버](RuntimeFlow.md)에서 먼저 수행한다. Sweep 솔버가 시작할 때는 그 결과 위치에서 이동 요청을 소비한다. `SweepBodyState` 구조체에 잔여 이동량, 슬라이드 횟수, `PushPriority`를 보관하며, 우선순위는 각 바디의 원래 `Priority`로 시작한다. Initial의 우선순위 버퍼를 받지 않으므로 Initial에서 승계한 벽 권한은 전달되지 않는다.

| 순서 | 처리 |
| --- | --- |
| 1 | 각 동적 바디의 요청 변위와 원래 우선순위로 `SweepBodyState` 생성 |
| 2 | 정적 후보와 동적 쌍에 대해 Shape Cast 수행 |
| 3 | 유효한 접촉 중 가장 작은 비율 선택 |
| 4 | 모든 바디를 각자의 남은 이동량 × 접촉 비율만큼 이동 |
| 5 | 같은 위치의 접촉 제약을 모으고 밀기·뒤따름·막힘 결과가 안정될 때까지 함께 계산 |
| 6 | 수정된 잔여 이동량으로 다시 경로 검사 |
| 종료 | 더 이상 유효한 접촉이 없으면 잔여 이동량 전체 적용 |

접촉 비율 `t`는 각 반복에서 현재 남은 변위에 대한 비율이다. 최초 요청 전체에 대한 누적 비율이나 초 단위 시간이 아니다.

## 정적 바디 검사

남은 이동이 있는 동적 바디의 Swept Bounds로 QuadTree를 조회한다. 정적 대상은 움직이지 않으므로 그 바디의 남은 변위를 그대로 Cast에 사용한다. 남은 변위가 없는 동적 바디는 정적 경로 검사를 생략한다.

## 동적 쌍과 상대 이동

동적 A와 B의 남은 이동량을 각각 `dA`, `dB`라고 하면, B를 고정한 상대 좌표계에서 A의 이동량은 다음과 같다.

$$
d_{relative}=d_A-d_B
$$

양쪽 Swept Bounds가 겹치는 쌍에 대해 이 상대 이동량으로 Shape Cast를 수행한다. A가 정지해 있어도 B가 A를 향해 이동하는 접촉을 검출할 수 있다. 둘 다 남은 이동이 없다면 검사하지 않는다.

상대 좌표계의 Cast가 반환한 법선만 이동 조정에 사용한다. Cast의 접촉점을 실제 두 바디가 동시에 이동한 월드 접촉점으로 그대로 사용하지 않는다.

## 이동을 막을 접촉 선택

법선 `n`은 상대 형상에서 바깥으로 향한다. 다음 결과는 최초 접촉 선택 전에 제외한다.

| 제외 조건 | 이유 |
| --- | --- |
| 스침 결과 | 표면을 스치는 경로를 막지 않기 위해 |
| `d · n ≥ -1e-6` | 표면 안쪽으로 접근하지 않거나 초기 접촉에서 빠져나가는 이동이기 때문 |
| 이미 선택한 비율보다 늦은 결과 | 가장 이른 접촉을 먼저 처리하기 위해 |

더 이른 접촉을 찾으면 이전 접촉 목록을 비운다. 같은 비율이면 함께 저장한다. 현재 구현은 비율의 정확한 비교로 동시 접촉을 묶으며, 별도의 시간 오차 범위로 합치지 않는다.

## 접촉까지 진행한 뒤 슬라이딩

현재 남은 변위를 `d`, 접촉 비율을 `t`로 두면 먼저 위치와 잔여 이동량을 갱신한다.

$$
\Delta position=d\,t,\qquad d_{remaining}=d(1-t)
$$

이후 남은 이동량의 법선 성분을 계산한다.

$$
s=d_{remaining}\cdot n
$$

`s < 0`이면 표면 안쪽 성분이 있으므로 이를 제거한다.

$$
d_{slide}=d_{remaining}-n\,s
$$

표면 밖으로 향하거나 표면과 나란한 성분은 유지한다. `ResolveContactMovements()`는 단일 접촉과 여러 접촉 모두를 법선 방향 이동량의 하한 제약으로 처리한다. 법선 `n`은 상대 B에서 자기 A 쪽을 향한다.

| 상대와의 관계 | A에 적용하는 제약 |
| --- | --- |
| 정적 표면 | `d_A · n ≥ 0` |
| 같은 유효 우선순위 | `d_A · n ≥ Min(0, d_B · n)` |
| 더 높은 유효 우선순위 | `d_A · n ≥ d_B · n` |
| 더 낮은 유효 우선순위 | A의 이동을 제한하지 않음 |

동급에서는 앞의 B가 멀어지고 있다면 A의 법선 이동을 B와 맞추고, B가 정지하거나 A를 향해 움직이면 A 자신의 안쪽 성분만 제거한다. 질량이나 운동량 보존에 따른 응답은 수행하지 않는다.

예를 들어 맞닿은 두 바디가 왼쪽으로 이동할 때 앞 바디의 요청이 `0.1`, 뒤 바디의 요청이 `0.2`라면 뒤 바디도 `0.1`씩 진행한다. 이 뒤따름 보정은 슬라이드 횟수를 소비하지 않는다. 이후 앞 바디가 완전히 멈추면 뒤 바디는 남겨둔 슬라이드 기회로 멈춘 상대의 접선을 따라 이동할 수 있다.

`ApplySweptMovements()`는 Solve 시작 중심과 누적 부분 이동량으로 현재 목표 중심을 계산한다. 작은 부분 이동을 월드 좌표에 반복 가산해 생기는 반올림 오차가 밀집 접촉에 누적되는 것을 줄인다. 접촉 비율이 `0`이면 위치를 갱신하지 않는다.

우선순위가 다르면 높은 바디의 잔여 이동량은 유지한다. 낮은 바디의 바깥 방향 법선을 `n`, 양쪽의 잔여 이동을 `d_low`, `d_high`라고 할 때 `s = (d_low - d_high) · n`을 계산하고, `s < 0`이면 낮은 바디만 `d_low -= n * s`로 조정한다. 상대 이동의 안쪽 성분을 제거하므로 높은 바디가 접근하면 정지한 낮은 바디도 밀려난다. 낮은 바디의 접선 방향 이동은 유지한다.

높은 바디의 접근에 실제로 밀리면 낮은 바디의 `PushPriority`를 승계한다. 밀려서 받은 법선 이동은 해당 접촉 단계의 목표 변위에도 남겨, 다음 계산에서 동급 판정으로 바뀌었다는 이유로 밀린 이동이 사라지지 않도록 한다. 같은 밀기를 목표 변위에 반복 가산하지 않는다. 따라서 `High → Low → Medium`의 전달도 유지된다. Sweep 종료 시 상태 목록을 비우고, 다음 Solve에는 각 바디의 원래 우선순위로 상태를 다시 만든다.

### 같은 위치의 연쇄 접촉 정리

최초 접촉 위치에서 이동량을 바꾸면서 새로 발생하는 비율 `0`의 접촉도 `activeContacts`에 모은다. 그 위치에 머무르는 동안 발견한 제약을 유지한다. 각 바디의 후보는 같은 이전 상태를 읽어 계산한 뒤 함께 반영하며, 이 계산 중에는 위치와 슬라이드 카운터를 갱신하지 않는다.

후보는 접촉 단계에 들어올 때의 목표 변위에서 다시 구한다. 직전 보정 결과를 법선별로 계속 잘라내지 않는다. `TryFindClosestMove()`는 모든 제약을 만족하는 원래 목표, 각 경계에 대한 투영, 두 경계의 교점, 영벡터를 비교해 목표에 가장 가까운 후보를 고른다. 움직이는 상대의 제약은 경계가 원점을 지나지 않을 수 있으므로 교점 후보도 필요하다. 이 과정은 정지 접촉과 이동 접촉에 공통으로 적용한다.

거의 반대 방향인 두 밀기의 경계 교점은 입력보다 훨씬 멀어질 수 있다. 이때 바디가 옆으로 급발진하지 않도록 후보 길이를 목표 이동 길이와 각 밀기가 직접 전달할 법선 보정 길이의 합으로 제한한다. 이 범위를 넘는 후보는 밀린 목표를 저장하는 단계와 최종 이동 계산 모두에서 제외한다.

동시 접촉의 최초 묶음은 기존처럼 정확히 같은 비율로 선택한다. 접촉 정리는 움직이는 바디의 전달과 한 위치의 순차 투영에 따른 순서 영향을 줄이지만, 초기 겹침 해소·부동소수점·반복 상한을 포함한 전체 시뮬레이션의 완전한 등록 순서 독립성을 보장하지 않는다.

## 정적 벽 슬라이딩 예시

반지름 `0.5`인 원이 `(0, 0)`에서 `(4, 2)`만큼 이동한다. 벽은 중심 `(3, 0)`, half extents `(1, 10)`인 박스이므로 왼쪽 면은 `x = 2`다.

| 단계 | 계산 결과 |
| --- | --- |
| 원이 닿을 때 중심 X | `2 - 0.5 = 1.5` |
| 최초 접촉 비율 | `1.5 / 4 = 0.375` |
| 접촉까지 이동 | `(4, 2) × 0.375 = (1.5, 0.75)` |
| 접촉 후 잔여 이동 | `(4, 2) × 0.625 = (2.5, 1.25)` |
| 접촉 법선 | `(-1, 0)` |
| 안쪽 성분의 크기 | `(2.5, 1.25) · (-1, 0) = -2.5` |
| 슬라이딩 변위 | `(2.5, 1.25) - (-1, 0) × -2.5 = (0, 1.25)` |
| 최종 중심 / 최종 이동량 | `(1.5, 2)` / `(1.5, 2)` |

벽 안쪽의 X 이동은 제거되지만 Y 이동은 끝까지 수행된다. 이 결과는 MTV로 밀어낸 위치가 아니라, 이동 경로의 접촉 시점과 잔여 이동의 투영으로 얻은 결과다.

## 동적 접촉 예시

반지름이 각각 `0.5`인 A와 B의 시작 중심을 `(0, 0)`, `(3, 0)`으로 두고, 요청 변위를 `(2, 0)`, `(-1, 0)`으로 둔다.

| 항목 | 결과 |
| --- | --- |
| 상대 이동량 | `(3, 0)` |
| 접촉까지 줄여야 할 간격 | `3 - (0.5 + 0.5) = 2` |
| 접촉 비율 | `2 / 3` |
| 접촉 시 중심 | A `(1.333333, 0)`, B `(2.333333, 0)` |
| 접촉 법선 | A `(-1, 0)`, B `(1, 0)` |
| 남은 이동량 | A `(0.666667, 0)`, B `(-0.333333, 0)` |
| 조정 후 남은 이동량 | 둘 다 표면 안쪽 성분만 있으므로 `(0, 0)` |

접촉에 참여하지 않은 동적 바디도 같은 비율만큼 진행한 뒤 자신의 잔여 이동을 계속 처리한다.

## 반복 제한과 현재 동작

실제 슬라이드는 `MaxSlideIterationCount = 1`을 유지한다. 접촉 계산이 안정된 뒤, 밀기·뒤따름만으로 만족시킬 수 없는 정지/대향 표면의 제약이 있으면 그 접촉 단계 전체에서 1회를 소비한다. 움직이는 앞 바디에 맞추는 뒤따름과 높은 우선순위에 밀리는 보정은 소비하지 않는다. 이미 1회를 쓴 바디가 이동 후 새로운 표면에서 추가 슬라이드를 해야 한다면 자신의 남은 이동을 포기한다. 높은 우선순위에 밀리는 이동은 계속 받을 수 있다.

접촉을 정리하는 내부 반복에는 슬라이드 횟수와 별도로 `Max(16, dynamicBodies.Count * 4)`의 상한과 변화량 판정을 둔다. 상한 또는 진행 정지에 도달해도 비율 `0`의 접근이 남으면 해당 미해결 접촉에 연결된 동적 바디 무리만 중단한다. 무관한 바디의 남은 이동은 계속한다. 제약을 동시에 만족하는 후보가 없는 중간 상태에서는 0을 사용하고, 우선순위 전달과 후속 계산에서 재평가한다.

이동 길이가 `1e-6` 이하이면 남은 이동이 없는 것으로 취급한다. 별도의 skin margin이나 이동 후 추가 MTV 보정은 포함하지 않는다. 내부 반복의 상한이 있으므로 임의의 밀집 배치에서 멈춤이 없거나 카메라가 안정적임을 보장하지는 않는다.
